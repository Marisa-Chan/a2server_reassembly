# Enum conversion worklist: magic constants -> named enums
#
# Follow-up to the PacketId enum (net.h, commit 52cd447a). Same idea: find a
# family of raw numeric constants, give every value a name in one enum, replace
# all usages, verify nothing changed semantically, one family per commit.
#
# Every fact below (values, semantics, file anchors, usage counts) was verified
# against the source on 2026-11-08. Where a value's meaning is marked RESEARCH,
# do the research before naming it; if you cannot settle it, leave that entry
# unnamed (raw value + TODO comment) or skip the family - never guess.
#
# Work the list top to bottom. Tick families off here when committed.

================================================================================
GROUND RULES
================================================================================

1. Build:      `tool/build.ps1` from the repo root. BOTH rea2s.exe and rea2c.exe
               must link. Filter output for: error | LNK | warning C | rea2s.exe | rea2c.exe
               (everything else is benign noise).
2. Commits:    ONE family per commit. Message: "Introduce <EnumName> enum; replace raw constants".
               Build in one command, commit in a SEPARATE command (never `... && git commit`
               after a build - a failed build must not be committed).
3. Enum style: unscoped enum with fixed underlying type, entries ALL_CAPS with
               underscores, aligned `=` column, one-line comment per entry with
               known semantics (see enum PacketId in src/net.h for the house style).
               The underlying type MUST match the field being compared/assigned
               (int32_t for int fields, uint8_t for byte fields, uint32_t for masks).
4. Placement:  next to the field it describes (its class header), or in the header
               owning the protocol concept. Packet-related enums go in src/net.h.
5. Code style: `this->` for member access, braces on all if/for bodies, no
               unnecessary casts, keep the original function-address comments.
6. Do NOT change any behavior. No "fixing" values, no reordering, no extra casts.
   If a site looks buggy, keep it byte-identical and note it in the commit message
   or a follow-up TODO.

================================================================================
GENERAL WORKFLOW (per family)
================================================================================

1. Inventory: count every raw usage of the family:
      grep -rnE "<pattern>" src --include=*.cpp --include=*.h | wc -l
   Record per-value counts BEFORE starting (you will compare after).
2. Check name collisions BEFORE choosing names:
      grep -rnE "\b<NAME>\b" src/*.h
   An enumerator must not share its exact name with a method/function/field of
   any class whose code mentions it unqualified (see Trap 3).
3. Write the enum in the right header; build once to see the enum compiles.
4. Replace usages, file by file. Replace ONLY the constant token in code
   positions - never inside comments or string literals (see Traps 1-2).
5. Verify (all three must pass):
   a) No raw constant of the family remains, except sites listed as EXEMPT:
          grep -rnE "<raw pattern>" src --include=*.cpp --include=*.h
   b) Per-value replacement counts match the before-counts (some sites combine
      two values on one line - count lines, not tokens).
   c) Full build green (both exes).
6. Commit. Update the checkbox in this file in the same commit.

================================================================================
TRAPS (all of these actually happened during the PacketId conversion)
================================================================================

Trap 1 - STRING LITERALS. A whole-word regex happily renames "GameSpeed" inside
  RegQueryValueExA(rkey, "GameSpeed", ...). That is a REGISTRY VALUE NAME - the
  program would silently read a different key. Mask out comments AND string
  literals before replacing; after replacing, diff all quoted strings against
  the pre-change commit:
      git show HEAD~1:src/<file> vs current - the multiset of "..." literals
  must be identical (write a tiny python checker; single-line pairing only).

Trap 2 - COMMENTS. "case CHAT: // Chat message." - the comment should stay
  English prose. Replace only the code token.

Trap 3 - MEMBER-NAME COLLISIONS. Enumerator GroupAttackMove coexisted legally
  with method World::GroupAttackMove; a blind whole-word rename renamed the
  METHOD and broke the build (caught by compiler) - but the reverse (renaming
  only some references) can compile and corrupt. Always do the collision grep
  (workflow step 2) first.

Trap 4 - HEAD TRUNCATION. `grep ... | head -40` hides matches mid-list; the
  PacketId inventory missed 8 senders that way. Count with `wc -l` and page
  through everything, or dump to a file.

Trap 5 - MULTI-TOKEN LINES. Lines like `case 0x65: case 0x67: case 0x97:` must
  keep every label; rewrite token-by-token within the line, never replace the
  whole line.

Trap 6 - grep on this box is ugrep: patterns starting with `-` need `-E -- "<pat>"`.

[x] 11. UnitUpdateField  (SendUnitUpdate update_mask, ~90 call sites)
    Opaque masks everywhere: 0xFFB, 0xffb, 0xFFFFFFFF, 0xA35FFFFF, 0x282000,

    Bit meanings are documented in the client PacketUnitUpdate handler,
    src/ingame.cpp ~556-790: 1=hp 2=mp 4=skill levels 8=hp/mp maxima
    0x10=dir+pos 0x20=type+face 0x40=owner 0x80=serverId 0x100=exp per sphere
    0x2000=carried weight 0x4000=defense 0x8000=absorb 0x10000=attack
    0x20000=hand damage 0x40000=scan range 0x80000=speed 0x100000=spells+
    active spell 0x1000000=magic protections 0x2000000=kill stats.
    Define bit constants UNIT_UPD_* (uint32_t) in src/net.h, then named
    combinations for the recurring masks (read the call sites to name them,

    WARNING: the SECOND argument of SendUnitUpdate (equip_mask, also 0xFFB-ish)
